### mgba-001 — Dispatch through a small table keyed on the opcode bits that matter
Lens: lookup-tables · Source: mGBA
Principle: Replace a decode tree with a function-pointer table indexed by only the distinguishing bits, and make each entry a handler that is already specialized. Decode becomes one indexed load and one indirect call. Keeping the table small keeps it in cache.
Why it is faster: —
Applies elsewhere: bytecode VMs (`handlers[op]()`), a tokenizer using a 256-entry character-class table, protocol parsers dispatching on message type.
Watch out: —
Seen in mGBA: The ARM table shrank from `_armTable[0x10000]` to `_armTable[0x1000]`, indexed by `((op>>16)&0xFF0)|((op>>4)&0xF)`. The Thumb table is generated by `DO_8`/`DO_256` preprocessor macros. Today the tables are `_armTable[0x1000]` and `_thumbTable[op>>6]` (1024 entries). b02fdd3dd 2013-04 “Remove inline conditions and add ARM specialization”; 76dbfce3c 2013-04 “Start filling in THUMB table with insane preprocessor tricks”

### mgba-002 — Hard-code the dominant case and check it first
Lens: branching-fast-paths · Source: mGBA
Principle: Write separate code paths per mode instead of reading mode-dependent function pointers and variables on every step, and test the most common case with a single predictable branch before any general handling. Collapse duplicated failure tails so the hot code stays small.
Why it is faster: —
Applies elsewhere: an HTTP router with a fast path for `GET /`, a JSON parser that tests for ASCII before decoding UTF-8, a codec with a dedicated 8-bit pixel path.
Watch out: —
Seen in mGBA: The `cpu->loadInstruction` function pointer and the `instructionWidth` variable were removed in favour of separate ARM and Thumb step functions. `if (condition == 0xE)` (always-execute) bypasses the 16-case switch, and the 16 duplicated `cycles += PREFETCH; return;` tails became one `conditionMet` flag. b02fdd3dd 2013-04 “Remove inline conditions and add ARM specialization”; 37ad6218d 2013-04 “Don't double-execute AL instructions”; 6cff3d423 2014-08 “Remove unnecessarily duplicated code in ARMStep”; 3c41bd242 2014-11 “ARM: Reduce size of ARM condition prediction”

### mgba-003 — Cache a direct pointer to the current partition
Lens: laziness · Source: mGBA
Principle: When nearly every lookup lands in the same partition, keep a base pointer and mask for that partition and recompute them only when the key moves to a different one. The common case becomes a masked array load instead of a dispatch.
Why it is faster: —
Applies elsewhere: a DB cursor keeps its current page pinned, a TLB, a segmented-array iterator caching its current chunk.
Watch out: —
Seen in mGBA: Instruction fetch used to call `memory->load32()`, an indirect call into a region switch. It became `activeRegion[(addr & activeMask)>>2]`, with `setActiveRegion` run only on PC writes, returning early when the region hasn't changed, and also caching that region's wait-state cost. d3abd2dc6 2013-04 “Minor ROM access optimization”; 1838cc059 2013-04 “Implement waitstate adjusting”; 7cb183a8b 2013-10 “Only update active region if necessary”; 1e1b0fc89 2014-08 “Check active region instead of pc for BIOS loads”

### mgba-004 — Inline the step and unswitch the hot loop
Lens: branching-fast-paths · Source: mGBA
Principle: Inline the per-iteration function, skip work an iteration won't use, and move invariant tests out of the loop by writing one loop per case. When the invariant changes, force the loop bound so the loop exits. The result is a small, branch-light loop body.
Why it is faster: —
Applies elsewhere: one inner loop per pixel format instead of a per-pixel switch; a parser running a separate loop for each encoding.
Watch out: —
Seen in mGBA: `ARMStep`/`ThumbStep` became `static inline`, and the table lookup now happens only after the condition passes. `ARMRunLoop` runs `while (cycles < nextEvent) step();` with one loop per CPU mode, and `_ARMSetMode` sets `nextEvent = 0` to break out of the loop. 52808da26 2014-01 “Inline CPU stepping”; 2553b96e9 2014-01 “Skip table lookup in ARMStep if not needed”; 433f0ba36 2014-08 “Tighter looping for ARMRun”; 845d6e1d2 2014-11 “ARM: Run tighter loop in CPU”

### mgba-005 — Schedule by next deadline instead of ticking everything
Lens: algorithms · Source: mGBA · Also: ares
Principle: Keep a single "time of the next interesting event" and service components only when it is reached, as in discrete-event simulation. The hot loop costs one compare per step, and idle components cost nothing.
Why it is faster: —
Applies elsewhere: timer heaps in game servers and event loops, a tickless OS kernel, a `setTimeout` queue.
Watch out: —
Seen in mGBA: The CPU calls `processEvents` only when `cycles >= nextEvent`. Each subsystem returns its next deadline, the minimum becomes the new `nextEvent`, and countdowns are reduced by `eventDiff`. The DMA path now adjusts only the channel that was serviced. Today this is the sorted event list in `mTiming`. 9b5d5d647 2013-04 “Start implementing events + add video stubs”; 3b74b6186 2013-11 “Move halting code out from below the ARM emulator”; 548793e55 2014-07 “Remove audio processing loop now that there is an event processing loop”; e7bd5f9ad 2014-10 “Remove loop in DMA to find a value we already know” • Also seen in ares (ares-044): `ng::OPNB::main()` decremented the FM and PCM-A counters and called `step(1)` on every pass. It now computes a `stepDuration`, subtracts it from both counters and calls `step(stepDuration)`. In the WonderSwan's inaccurate mode, `APU::main` runs 128 iterations before calling `step(128)`, and `PPU::main` renders the whole line before a single `step(224+32)`. The commit reports about a 65% speedup. d75c13107 2022-07 “ng: avoid syncing with the YM2610 more than necessary” · 6b70091f6 2022-12 “ws: support pixel inaccuracy mode, for per-scanline PPU and fast APU processing”

### mgba-006 — Replace busy-waiting with a jump to the next event
Lens: laziness · Source: mGBA
Principle: Detect polling or spin loops and turn them into "sleep until the next event", advancing simulated time directly. Time spent waiting then costs no host cycles.
Why it is faster: —
Applies elsewhere: condition variables or futexes instead of `while(!flag){}`, a test fake clock that jumps to the next timer.
Watch out: —
Seen in mGBA: `GBAHalt` sets `cycles = nextEvent` and then processes events in a loop while halted, never stepping the CPU. The HLE IntrWait now writes HALTCNT instead of spinning. Per-game `busyLoop` addresses trigger a halt from `setActiveRegion`; this later became automatic idle-loop detection. 8c03c2001 2013-04 “Implement HALT”; ee344f0dc 2013-10 “Optimize and fix IntrWait…”; 3b74b6186 2013-11 “Move halting code out from below the ARM emulator”; 5189d9afd 2014-07 “Add mechanism for adding halts to busy loops”; 4d2ccd5df 2014-08 “Add busy loop optimization back”

### mgba-007 — Keep a lookahead register instead of re-fetching
Lens: laziness · Source: mGBA
Principle: Hold a value you have already fetched and will need again (here, the next instruction) in a field. Code that would otherwise re-read memory through slow paths just reads the field.
Why it is faster: —
Applies elsewhere: a lexer with one-token lookahead, a stream reader keeping a peeked byte.
Watch out: —
Seen in mGBA: Each step now loads the next opcode into `cpu->prefetch`. Open-bus reads and the BIOS-protection path read `cpu->prefetch` instead of calling `load32(currentPC+8)` through a function pointer. Today this is a two-entry `prefetch[2]`. baa71027e 2014-08 “Reimplement prefetch, temporarily removing busy loop optimization”

### mgba-008 — Accumulate in locals and write back once
Lens: memory-layout · Source: mGBA
Principle: Updating a field through a pointer forces a load-modify-store each time and blocks optimization because of possible aliasing. Accumulate into a local that can stay in a register and commit it once at the end.
Why it is faster: —
Applies elsewhere: sum into `long total` in a loop, then assign `obj->total` once; cache `this.count` in a local in JS.
Watch out: —
Seen in mGBA: The multiply wait-state macros changed from `cpu->cycles += N` to `currentCycles += N`, which is committed once per instruction. 9e400e86d 2014-11 “ARM: multiply wait macros should write to local variable instead of global cycle count”

### mgba-009 — Normalize switch keys into a dense range
Lens: branching-fast-paths · Source: mGBA
Principle: Shift or scale sparse case constants down to small consecutive integers so the compiler emits a bounds check plus a jump table instead of a chain of comparisons.
Why it is faster: —
Applies elsewhere: `switch (status/100)`, dispatching on `(addr >> 12)` page numbers in an MMIO decoder.
Watch out: —
Seen in mGBA: `switch (address & ~OFFSET_MASK)` with sparse cases like `0x08000000` became `switch (address >> BASE_OFFSET)` with cases `REGION_*` 0–15. a825c6e4a 2014-08 “Use bitshift instead of bitmask for determining load/store region”

### mgba-010 — Batch operations that share a dispatch decision
Lens: algorithms · Source: mGBA
Principle: Classify once per batch, then run a loop specialized for that class. Unroll it, and mark the per-element tests with likely/unlikely hints. One dispatch and one indirect call cover many elements.
Why it is faster: —
Applies elsewhere: a multi-row `INSERT`, `writev` instead of N writes, bulk DOM updates in one fragment.
Watch out: —
Seen in mGBA: LDM/STM used to call `memory.load32` through a function pointer once per register. Now `GBALoadMultiple`/`GBAStoreMultiple` switch on the region once and run a region-specialized `LDM_LOOP(LOAD_x)`, unrolled by 4 with `UNLIKELY(mask & (k<<i))` on each bit test. 537480b94 2014-10 “Load/Store multiple functions”; a57312d0c 2014-10 “Refine and reuse STM/LDM code”; 37554a40e 2014-10 “Add likely/unlikely macros”; d49df216b 2014-11 “GBA Memory: Simplify LDM/STM loop”; 0308f136c 2014-11 “GBA Memory: partially unroll loops for LDM/STM and add UNLIKELYs”

### mgba-011 — Count bits with SWAR arithmetic and check what intrinsics compile to
Lens: algorithms · Source: mGBA
Principle: Bit-parallel arithmetic counts set bits in about 12 ALU ops with no branches. A compiler builtin can turn into a slow library call when the target has no native instruction, so check the generated code.
Why it is faster: —
Applies elsewhere: Bloom filters, bitmap indexes, chess bitboards.
Watch out: —
Seen in mGBA: A 16-iteration bit loop was replaced by `__builtin_popcount`, and then by the SWAR formula `x-((x>>1)&0x55555555)…*0x1010101>>24`. It is still used today as `popcount32`. 9abe700d3 2014-10 “Use GCC popcount intrinsic for popcount”; 1619b760e 2014-10 “Use better popcount than the GCC one...”

### mgba-012 — Branch-free range checks with power-of-two bounds
Lens: branching-fast-paths · Source: mGBA
Principle: When a bound is a power of two, OR the coordinates together and test them against the inverted mask. This checks for negative values and overflow on both axes in one test. Pick shift forms that map onto native rotates.
Why it is faster: —
Applies elsewhere: tile or texture-atlas bounds checks, ring-buffer index validation.
Watch out: —
Seen in mGBA: `x<0||y<0||x>=size||y>=size` became `(x|y) & ~(size-1)`. The 16-bit rotate dropped its mask and became `(v>>r)|(v<<(16-r))`. 9253eeba2 2013-11 “Optimize range check in mode 2 rendering”; 72ef1643c 2013-10 “Rotate 16-bit without using AND”

### mgba-013 — Put the sort key in a value's top bits so ordering is one compare
Lens: memory-layout · Source: mGBA
Principle: Pack metadata into the high bits of the data word, with priority in the most significant bits. Deciding order becomes a single integer comparison, and reading the metadata needs no second array or memset. Test the most common state first.
Why it is faster: —
Applies elsewhere: 64-bit draw-call sort keys `(layer<<56)|(depth<<32)|material`, tombstone flags packed into index entries.
Watch out: —
Seen in mGBA: The separate `PixelFlags` array was removed. Each `uint32_t row[x]` now holds the color plus `FLAG_PRIORITY`/`TARGET`/`OBJWIN`/`UNWRITTEN` in its top byte, and `_composite` orders layers with `if (color < current)`. The unwritten case is tested first, and stricter layer ordering removed the "finalized" test. 754725e12 2013-04 “Start using pixel flags to keep track of pixel states”; 3ad2510b7 2013-05 “Get rid of flags struct and redo compositing”; f5a3fd7c7 2013-10 “Rearrange _composite to optimize for common cases first”; 32e0591fd 2013-11 “Early finalization if possible”; 55c610311 2013-11 “Remove "finalized" flag in favor of stricter sorting”

### mgba-014 — Work at the data's natural block size and skip empty blocks
Lens: algorithms · Source: mGBA
Principle: Load a whole word or block and peel its sub-elements off with shifts in an unrolled body. Test the whole block once for the trivial case (all zero, transparent) so it can be skipped. Lookups drop by the block factor.
Why it is faster: —
Applies elsewhere: testing 64-bit bitmap words for zero before scanning bits, word-at-a-time `memchr`, sparse-matrix block skipping.
Watch out: —
Seen in mGBA: The renderer used to compute the tile address and composite per output pixel. Now it loads `tileData = ((uint32_t*)vram)[charBase]` once per 8-pixel tile, then repeats `tileData >>= 4` in an 8× unrolled body. `if (tileData)` skips transparent tiles, and horizontally flipped tiles get their own unrolled path. 7bb4d9d5f 2013-04 “Throw out slow background renderer. ### mgba-015 — Generate specialized loop bodies for invariant modes
Lens: branching-fast-paths · Source: mGBA
Principle: When a mode is fixed for a whole batch, choose a pre-instantiated loop variant once instead of branching per element. Where variants differ only in data, pass a pointer instead, so code doesn't bloat. Route identity configurations to the cheap path.
Why it is faster: —
Applies elsewhere: `blit_opaque` vs `blit_alpha`, C++ policy templates, a shader permutation per feature set.
Watch out: —
Seen in mGBA: One `_composite` was split into four inline variants (Blend/NoBlend × Objwin/NoObjwin), selected through `COMPOSITE_16_##BLEND` macros. Duplicated NORMAL/VARIANT macros were replaced by a palette pointer. ### mgba-016 — Transform at write time, not read time
Lens: lookup-tables · Source: mGBA
Principle: If an input changes rarely but is read constantly, precompute its derived forms when it is written. Here a 512-entry palette changes occasionally while about 38K pixels per frame read it.
Why it is faster: —
Applies elsewhere: storing pre-normalized search keys, computing theme-derived colors when the theme changes, materialized views.
Watch out: —

Lens: memory-layout · Source: mGBA

### mgba-019 — Step linear functions by their delta (strength reduction)
Lens: algorithms · Source: mGBA
Principle: A linear function evaluated at evenly spaced points can be updated by adding a constant each step instead of recomputing products, so additions replace multiplications in the inner loop.
Why it is faster: —
Applies elsewhere: DDA line and gradient rasterization, generating evenly spaced timestamps, texture-coordinate interpolation.
Watch out: —
Seen in mGBA: For affine (rotated and scaled) sprites, each pixel used to compute `(a*(inX-w/2)+b*(inY-h/2))>>8`, which is four multiplies. Now `xAccum`/`yAccum` are set once per row and updated per pixel with `xAccum += mat.a; yAccum += mat.c;`. fd5b95024 2014-10 “Clean up transformed sprite rendering using accumulators”

### mgba-020 — Composite in a small hot scratch buffer, then copy out once
Lens: memory-layout · Source: mGBA
Principle: Run multi-pass read-modify-write work in a small buffer that stays in cache, next to the other state the code uses, and publish the result to the large destination with one sequential copy.
Why it is faster: —
Applies elsewhere: tile-based canvas compositing, formatting into a stack buffer and then one `write()`.
Watch out: —

### mgba-021 — SWAR: one multiply blends several packed fields
Lens: simd · Source: mGBA
Principle: Spread small fields across a wide integer with guard bits between them, so one multiply-add processes every field at once. Use native-width types for temporaries to avoid extra truncation and extension instructions.
Why it is faster: —
Applies elsewhere: blending RGBA8888 with `c & 0x00FF00FF` and `(c>>8) & 0x00FF00FF`, packed counters.
Watch out: —
Seen in mGBA: In 5-6-5 alpha blending, green is moved to bit 16 and above (`a |= (colorA&0x7C0)<<16`) so a single `(a*wA+b*wB)/16` blends R, G and B together, replacing three separate multiply sequences. Lens: io · Source: mGBA

### mgba-030 — Filter at the source so disabled logging and checks cost nothing

### mgba-081 — Memoize output units on a fingerprint of their inputs

### mgba-082 — Compare before storing so unchanged writes don't invalidate anything
