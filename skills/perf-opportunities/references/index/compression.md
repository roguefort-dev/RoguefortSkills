# Lens: compression (37 techniques)

Lightweight encodings, per-block codec choice, operating on encoded data.

Format: `id | title | principle (first sentence)`. The id prefix names the cards file: `../cards/<prefix>.md`.

- duckdb-067 | Keep data encoded through execution and work once per distinct value | Let in-memory batches carry their encoding (constant, sequence, dictionary plus indices) from storage through operators to writers.
- duckdb-068 | Let codecs compete per block: analyze cheaply, pick the smallest, fall back to raw | Don't hard-code one encoding per type. For each block, let every candidate codec estimate (or actually produce) its output size, keep the winner, and store the block uncompressed when nothing beats raw. (also: zstd)
- duckdb-069 | Narrow values before materializing them (frame of reference on intermediates) | Before data enters anything that buffers, hashes, sorts or spills it, use known value ranges to subtract the minimum and cast to the smallest unsigned type that fits.
- duckdb-070 | Bitpack integers with frame-of-reference and delta modes | Per small group (such as 32 values), subtract a reference (the min, or the previous value for deltas) and store each value in the minimum number of bits.
- duckdb-071 | Dictionary-encode repetitive strings per block, with a purpose-built builder | Store each distinct value once per block and replace occurrences with small (bitpacked) codes.
- duckdb-072 | Encode runs, constants and sparse bitmaps compactly | Store repetitive data as (value, run length) pairs.
- duckdb-073 | Push filters and row selections into the decoder | Give each codec two operations: "which rows match this predicate" (evaluated on encoded data where possible) and "decode only these rows".
- duckdb-074 | Write each decoder for its common case | When scans are decode-bound, rewrite each encoding's inner loop for the dominant shape: fewer per-value branches, bulk copies for long runs, structure-of-arrays metadata unpacked up front, and table-driven…
- duckdb-075 | Use heavyweight compression only where it pays: cold or large values, and adaptively for spill | General-purpose codecs (gzip, zstd) get great ratios but cost CPU on every access.
- duckdb-076 | Compress strings with a per-block symbol table that keeps each string separately decodable (FSST) | Replace frequent 1-8 byte substrings with 1-byte codes from a small per-segment symbol table.
- duckdb-077 | Compress floats by exploiting their structure: XOR with similar neighbours, or recover hidden decimals (Chimp/Patas, ALP) | Consecutive floats share sign, exponent and high mantissa bits, so XOR each value with a well-matching recent value and store only the meaningful bits.
- simdjson-087 | Parse decimals as an exact integer mantissa plus a power, with a tiny correctly-rounded fast path | Accumulate the digits into a 64-bit integer and track the decimal exponent, then convert with one multiply by a precomputed power.
- simdjson-088 | Own the rare slow path: bigint comparison instead of decimal simulation, and no locale-dependent library calls | When a fast algorithm needs a fallback, make that fallback self-contained and algorithmically cheap, because adversarial or unusual inputs live there and library calls bring hidden costs.
- simdjson-089 | Check and convert eight ASCII digits as one 64-bit word (SWAR) | Load 8 digit bytes as a single integer, test them all for digit-ness with two mask operations, and combine them into a number with three multiply-shift steps instead of eight dependent multiply-adds.
- simdjson-090 | Make variable-length digit runs branch-free and size digit blocks to the real length distribution | When the number of digits varies unpredictably, compute it from a mask and run the same instructions for every length; when it is skewed, pick block sizes (8, 4) that match the lengths that actually occur.
- simdjson-091 | Check integer overflow once from the digit count, not per digit | Let the accumulation wrap freely and decide overflow afterwards from how many digits there were; only the single boundary length needs a comparison.
- simdjson-092 | Classify a number's type by scanning, and parse dynamically typed numbers once into a tagged value | If the caller only needs to know which numeric type a token is, answer from a digit scan without converting; if the type is unknown, convert once into a small tagged union rather than trying each type in turn.
- simdjson-094 | Format floats with a shortest-round-trip algorithm and fixed-width digit emission | Use a modern shortest-representation algorithm that needs one or two wide multiplies, then convert the digit block as a fixed-width integer rather than digit by digit, skipping halves that are zero.
- simdjson-095 | Unescape strings by copying whole blocks unconditionally and patching only at escapes | Copy a full vector of bytes to the destination on every step while computing where the terminator and the first escape are; if the terminator comes first you are done, otherwise handle one escape and continue.
- simdjson-098 | Take the position from the same mask that answered "is there one?" | When a vector test detects that a block contains a special byte, derive its index directly from the compare mask instead of following up with a separate scalar search.
- simdjson-100 | Write short decoded strings straight into the destination's inline buffer | When the target string type has small-buffer optimisation, fill its inline storage directly for short, escape-free strings; otherwise decode into scratch space and roll the scratch pointer back afterwards.
- zstd-110 | Split a mixed token stream into homogeneous sub-streams, each with its own model | When one output interleaves fields with different statistics, store each field kind in its own array and code it with its own table.
- zstd-112 | Reuse the previous unit's coding table when it is still valid and still cheap | Keep the last table. Before building a new one, check that the old one can encode every symbol present and that its estimated size is no worse than a new table plus its header. Track this per table.
- zstd-113 | Encode one long serial bitstream as several independently decodable streams | Split the payload into 2 to 4 independent bitstreams with a small table of stream sizes, and decode one symbol from each in turn inside a single loop.
- zstd-114 | Design the bit reader around a wide container, plain shift-and-mask and a cheap refill | Keep bits in a register-wide container. Extract fields with the simplest shift and mask. Refill with a single bounds test, and make overflow safe by construction instead of checking it on every read.
- zstd-115 | Pack each code into one word and write through independent accumulators | Store each code as one machine word holding value and length.
- zstd-116 | Use table-driven ANS with per-symbol transforms precomputed at table build | tANS (Finite State Entropy) gets close to arithmetic-coding ratio at Huffman-like speed.
- zstd-117 | Code wide-range integers as an entropy-coded bucket plus raw extra bits | Map each value to a small code (exact for small values, log-spaced for large ones), entropy-code the code, and append raw extra bits.
- zstd-118 | Make headers size-dependent, imply what can be derived, and compress table descriptions | Use 1, 2 or 3-byte header forms by magnitude and use each form's full range.
- zstd-119 | Count symbols into several private sub-tables and merge in a fixed-length pass | Spread histogram increments over several counter tables so repeated symbols do not serialise on one counter.
- zstd-120 | Look up all codes first, then fetch extra bits, skipping zero-length reads | When a record has several table-coded fields with extra bits, do all the independent table lookups first, then read the extra bits.
- zstd-121 | Size the coding table to the input, and search table depth for minimum total size | Choose table size (and stream count) from the number of symbols.
- zstd-122 | Build length-limited prefix codes by repaying a Kraft debt, and sort symbols with buckets | Build the optimal Huffman tree, cap code lengths, then repay the resulting Kraft-sum debt by lengthening the cheapest codes.
- zstd-123 | Build decode tables with fixed-length, branch-free fills | Replace "for each symbol, write it `count` times" with phases that have fixed inner lengths: group symbols by run length, or write contiguously with wide stores and then scatter with a fixed-stride loop.
- zstd-124 | Parse table headers with bit tricks and bulk operations, not bit-by-bit loops | Decode a header's run-length flags with count-trailing-zeros.
- zstd-125 | Pick between a small single-symbol and a large multi-symbol decode table with a calibrated cost model | Offer a table that decodes 1 symbol per lookup and one that decodes 2 or more.
- zstd-126 | Split oversize bit-fields across a refill only on the rare path, and compile the path out where it cannot occur | Size the common path for fields that fit the accumulator between refills.
