# Lens: scheduling (86 techniques)

Event scheduling, task queues, timers, pacing, latency and fairness.

Format: `id | title | principle (first sentence)`. The id prefix names the cards file: `../cards/<prefix>.md`.

- curl-020 | Drive many operations from one thread with resumable state machines | Write each protocol step as a state that returns "would block" instead of blocking, so a single thread can multiplex many operations over one readiness wait.
- curl-021 | Register exactly the readiness the operation can act on | Wait for readable only when you will read, for writable only when you have something you are allowed to send, and for nothing while paused or throttled.
- curl-022 | Keep running the state machine until it would actually block | After a transition that needed no I/O, run the next state immediately in the same call.
- curl-023 | Cap work per wakeup, then reschedule through the timer queue | Draining a socket until EAGAIN maximizes throughput for one stream but starves everything else on the loop.
- curl-024 | Arm timers only when they change, can matter, and are not for yourself | Notify the application's timer only when the earliest deadline actually changes, keep a "check again in X" only if it is earlier than what is already pending, never arm a wakeup for the task that is currently…
- curl-025 | Match timer precision to what the loop can act on | Round waits up, never report 0 ms for a deadline that is still in the future, return 0 at once when the deadline has passed, keep only the slack the OS clock really needs, and clamp the caller's wait to the…
- curl-026 | Report only changes in socket interest, combined per socket | Instead of rebuilding a full descriptor set every iteration, keep the last interest per socket, compare, and tell the event loop only about differences.
- curl-027 | Consume data buffered above the socket before waiting on the socket | When a lower layer (TLS library, SSH library, your own read cache) has already pulled bytes off the socket, the socket will not become readable for them.
- curl-028 | When there is nothing to wait on, sleep sensibly instead of spinning | A wait call with no descriptors returns immediately, so naive loops spin.
- curl-029 | Replace completion polling and sleeps with an event the loop can wait on | When a worker thread or another input source finishes, have it write to a descriptor the event loop already watches, rather than having the loop poll on a timer or sleep for a fixed time.
- curl-030 | Mark tasks dirty instead of faking timers or events | When one component needs another to run as soon as possible, set its bit in a dirty set.
- curl-031 | When capacity frees up, wake one waiter, not all | On an event that frees one slot, move one pending task to runnable.
- curl-032 | Rate limiting as a scheduler state with a computed wakeup | When a transfer exceeds its byte budget, park it in a state that registers no sockets and arm a timer for exactly when it may continue.
- flycast-131 | Measure throughput and shed optional work when behind | Track real speed over a short sliding window.
- haproxy-017 | Give each thread its own run queue and timer queue; share only what must be shared | Most tasks are only ever run by one thread, so give every thread private run and wait queues that need no lock, and handle the rare cross-thread case through per-thread inboxes or by messaging the owner.
- haproxy-018 | Keep timers and run queues in ordered intrusive trees | Store pending timers and runnable tasks in an ordered tree whose node is embedded in the task, so insertion is O(log n) with no allocation and "next to expire" is the leftmost node.
- haproxy-019 | Requeue timers lazily: treat the tree key as a lower bound | Timeouts are mostly extended and rarely fire, so leave a timer at its old, earlier position and fix it only if the expiry scan reaches it before its real deadline; never requeue on every I/O event.
- haproxy-020 | Use a lightweight FIFO lane for callbacks that need no priority or timer | I/O completions and handoffs do not need ordering or timeouts, so push them on a plain per-thread list instead of the ordered, locked run queue; resumed work that was already ordered once can skip the queue…
- haproxy-021 | Split runnable work into classes with CPU budgets; isolate heavy and self-requeuing work | Run urgent, normal, bulk and heavy work from separate queues with budgeted shares, demote work that keeps re-waking itself, allow at most one heavy item per loop, and let unused budget flow to the next class.
- haproxy-022 | Bound the batch run per loop iteration, and re-derive the bound when the architecture changes | Cap how many tasks run between two polls so I/O and other queues are serviced regularly, run each task at most once per pass, and recompute the cap when the scheduler's structure changes.
- haproxy-023 | Give long operations a per-call budget and make them yield | Any loop whose length depends on input or configuration (rule lists, purges, peer updates, frames in a buffer, interpreted code) must process a bounded quantum, save its position and requeue itself.
- haproxy-024 | Run newly woken follow-up work in the same pass, right after its producer | When a task wakes another during this loop iteration, run it before polling again, and insert it right after the current task so it uses the data while it is still in cache.
- haproxy-025 | Summarize "who has work" in per-thread or per-queue bits | Keep one bit per thread or per queue, set on enqueue and cleared when drained, so "any work for me?" and "which queue?" are a single load and test; drop the summary if it is more expensive to maintain than to…
- haproxy-026 | Wake exactly the thread that has work, and let one waker do the broadcasting | When handing work to a sleeping thread, signal only that thread through its own wake channel, and when many producers would wake the same subscribers, let one thread at a time own the wake-up duty.
- haproxy-027 | Make wakeups readiness-driven, not speculative | Instead of waking a consumer "just in case", let it subscribe: if the resource is already ready, schedule it immediately, otherwise arm the event; skip wakeups for consumers that declared they will not…
- haproxy-028 | Spread periodic and background work across threads and time; desynchronize it | Avoid having all threads (or all instances) act at the same moment or on the same target: keep periodic tasks bound but migrate them toward a randomly sampled less-loaded thread, randomize start points, and…
- haproxy-029 | Give each periodic maintenance task an owner thread instead of a run-anywhere janitor | Bind each instance of a periodic task (expiry, purge, sync) to one thread and rotate the assignment across instances, or run one janitor per thread over that thread's own data.
- haproxy-030 | Admit expensive operations through a bounded, load-aware queue | Limit how many CPU-heavy operations run concurrently per thread, queue the rest in order, and shrink the concurrency you offer to new clients when a smoothed load metric exceeds a target.
- haproxy-031 | Sleep until the moment work becomes possible, instead of polling or re-waking | Compute when a limit lifts, a pacing credit refills or a retry is likely to succeed, and arm a timer for that moment; drop periodic wakeups whose reason is gone.
- netty-012 | Run inline when already on the owning thread; enqueue (fused) only when crossing threads | Before posting work to a single-threaded executor, check whether the caller already is that executor's thread.
- netty-013 | Coalesce and skip wakeups of a sleeping loop | Waking a thread blocked in `select`/`epoll_wait` costs a syscall plus a context switch.
- netty-014 | Submit effect-free tasks without waking the loop | Some tasks only need to run in order before the next task that has a visible effect.
- netty-015 | Hashed timing wheels for huge numbers of mostly-cancelled timeouts | When most timeouts are cancelled before they fire (I/O idle or read timeouts), hash them into buckets by tick for O(1) insert and cancel, trading exact timing for tick-level granularity.
- netty-016 | Indexed heaps and eager removal for cancellable scheduled tasks | If scheduled tasks can be cancelled, store each element's heap index inside the element so removal is O(log n), remove cancelled tasks promptly, and skip cancelled entries before they reach the run queue.
- netty-017 | Bound the work any one source can do per loop turn | In a shared loop, give each connection or task source a budget per turn (syscalls, messages, delegated tasks) and yield when it is spent.
- netty-018 | Order work inside an iteration so it frees resources first | Within one loop turn, run the step that releases memory or unblocks others before the step that creates more work: I/O before queued tasks, draining writes before reading new input.
- netty-019 | Spin (busy-poll) before blocking, as an opt-in latency mode | When pending work is likely to appear within microseconds, poll without blocking (with a CPU pause hint) instead of sleeping in the kernel and paying for a wakeup.
- netty-020 | Read the clock once per batch, not once per item | Take one timestamp per loop iteration or read burst and reuse it for every message, timeout and deadline computed in that batch.
- netty-021 | Schedule a per-key serial runner only on the empty-to-non-empty transition | For ordered execution per key (per connection, per entity), give each key a queue.
- netty-022 | Size and choose event-loop threads from measurement, and let them scale | Pick the number of I/O threads by measuring, not by assumption.
- netty-023 | Detect a spinning poller and rebuild it | If the blocking wait keeps returning immediately with nothing to do, the poller is broken (a JDK epoll bug, or an error storm).
- pcsx2-061 | Tune the time-slice and event granularity of cooperative units | When several simulated or cooperative components share one thread, the slice length sets the trade-off.
- pcsx2-062 | Complete trivially short asynchronous work synchronously | Putting an event on a timed queue costs an insertion, a later dispatch and extra bookkeeping.
- pcsx2-279 | Sync coprocessors at their next event, not on a fixed time slice | Synchronizing two simulated processors on a fixed small interval forces many context switches that change nothing.
- seastar-014 | Turn every event source into a poller checked by one loop | On a dedicated core, check each event source (I/O completions, timers, signals, cross-thread queues, helper-thread results) by reading memory or making a zero-timeout call once per loop iteration, instead of…
- seastar-015 | Poll while busy, then switch sources to wake-up mode and sleep when idle | After a short idle period, ask every event source to arm a wake-capable notification (any source can veto if work raced in), then block.
- seastar-016 | Bound cooperative run time with a time quota, not a task count | A cooperative scheduler should yield to I/O polling when a fixed time slice has elapsed, measured by a timer that sets a flag, rather than after N tasks or continuations.
- seastar-017 | Make the "time to yield" flag nearly free to set and to check | Have the time-slice signal land as a plain memory write that hot code polls with a relaxed load, ideally written by the kernel or hardware directly, so neither setting nor checking it needs signals, wakeups…
- seastar-018 | Check for preemption once per loop iteration or await, not at every step | Put the yield check at loop back-edges and suspension points, which is enough to bound latency.
- seastar-019 | Keep the yield machinery itself from dominating under backlog | When the system is forced to keep running (large backlog) or forced to yield often (test modes), make sure the "preempted" slow mode doesn't become the steady state.
- seastar-020 | Schedule task groups by proportional share with virtual runtime | Give each class of work (foreground, compaction, streaming) its own queue with a share.
- seastar-021 | Give urgent and just-readied work a front-of-queue lane | Let urgent work (memory reclaim, the continuation of a value that just became ready) jump to the head of the run queue, and give yields a forced poll so that yielding is actually fair.
- seastar-022 | Carry the scheduling class across threads, shards and RPC automatically | Work spawned on behalf of a request (on another core, in a helper thread, on a remote server) should inherit that request's priority class without the application having to plumb it through.
- seastar-023 | Order pipeline stages within one loop iteration to minimize hops | When a loop runs several pollers in sequence, order them so that work produced by one stage is consumed by the next in the same iteration: inbound messages before outbound submission, timers before dispatch.
- seastar-024 | Isolate blocking offload work by class, and signal each completion promptly | Give latency-critical blocking work its own helper thread or queue, separate from slow unrelated calls, and wake the event loop after each completion rather than after a whole batch.
- seastar-025 | Do the work on the caller's task instead of handing it to a background worker | When a hand-off queue plus a background fiber exists only to serialize work, chain the work directly from the caller when it's uncontended, and keep just enough bookkeeping for cancellation.
- seastar-026 | Push unavoidable preparatory work onto idle-priority threads | Work that must happen eventually but not on the critical path (page faulting, hugepage collapse) should run ahead of time on low-priority background threads, so latency-critical code never pays for it.
- seastar-027 | Bound every queue and make producers pay for overflow | Cap in-flight work at each stage (per-destination queues, cross-core requests, batching stages), and when a cap is hit make the producer wait or do the flushing itself, instead of buffering without limit.
- snes9x-028 | Sample input as late as possible in the frame | Where the main loop yields to read input decides how stale that input is when the next frame is computed.
- snes9x-029 | Force a GPU sync after present, touching as little data as possible | Drivers queue several frames ahead, which adds latency.
- tokio-008 | Private per-worker queues plus one shared injection queue, with an atomic length in front of its lock | Give each worker a private run queue for work it creates, and send work from outside the pool to a single shared queue that any free worker drains.
- tokio-009 | Same-thread submissions skip synchronization | If the code scheduling work is already running on the thread that owns the target queue, push to an unsynchronized local structure.
- tokio-010 | A "run next" slot for the most recently woken task, capped for fairness | When the running task wakes another, run the woken one next from a one-element slot ahead of the FIFO queue, because its data is still in cache.
- tokio-011 | Steal half of the victim's queue in one claim, and run one stolen task immediately | An idle worker should take a batch (half of what the victim has), not one item.
- tokio-012 | Spill and refill in batches: one lock per half-queue, and spill the newest half | When a bounded local queue overflows, move half of it to the shared queue in one locked operation.
- tokio-013 | Check the shared queue first every N ticks, with N tuned from measured task cost | Prefer cheap local work, but every Nth scheduling tick look at the shared queue first.
- tokio-014 | Poll the event source with a zero timeout while busy; never block-park with work pending | A busy executor must still look at I/O and timers periodically, without blocking.
- tokio-015 | Throttle idle-worker wakeups: cap searchers, wake only when nobody is searching, chain the rest | When new work appears, wake a sleeping worker only if no worker is already looking for work, and let the last searcher that finds work wake exactly one more.
- tokio-016 | Signal a thread only if it is actually parked; coalesce repeated wakes into one | Before issuing a wakeup syscall, check (with one atomic swap) whether the target is asleep and whether a wake is already pending.
- tokio-017 | Make the event poller the thread parker, and let one idle worker at a time own it | Implement "sleep until there is work" as "block in the I/O poller with a timeout for the next timer".
- tokio-018 | Spin briefly before parking, and measure how brief | An idle worker should make a few cheap attempts to find work (spin with yield, or extra steal rounds) before paying for sleep and wakeup.
- tokio-019 | When a task must block, hand off the worker's queues, not the task | If code on a scheduler thread is about to block, give that thread's scheduling state (run queue, driver role) to another thread and block in place.
- tokio-020 | An elastic blocking pool: reuse idle threads, count notifications exactly, scan shards fairly | Run blocking jobs on a separate pool that keeps idle threads alive for a timeout and hands new jobs to an idle thread before spawning.
- tokio-021 | Cooperative preemption: a per-task operation budget in a thread-local counter | Without preemption, a task whose inputs are always ready never yields.
- tokio-022 | Budget accounting rules: charge only for progress, after acquisition, and exempt watchdogs | Deduct from a fairness budget only when an operation actually made progress, and only after a fair resource has been granted.
- tokio-023 | Yield to a deferred list that is flushed after the event driver runs | A task that yields voluntarily (or is out of budget) should go behind pending I/O and timer events.
- tokio-024 | Rotate or randomize the starting point when polling many sources, and wake waiters oldest-first | When one task multiplexes several sources, don't always poll them in the same order.
- tokio-104 | Register a timer only when someone actually waits on it | Creating a timeout should only record the deadline.
- tokio-105 | Push a deadline later without touching the timer structure | When a timeout only moves later (idle timeouts refreshed on activity), update the true deadline atomically and leave the entry in its old slot.
- tokio-106 | Reset an existing timer instead of dropping it and creating a new one | A periodic or repeatedly re-armed timeout should reuse its timer entry by changing the deadline in place.
- tokio-107 | Cancel timers as soon as they stop mattering; complete expired ones without registering | Remove a timer the moment the event it guards has happened.
- tokio-108 | Give each worker its own timer structure; send cross-thread changes as messages | A single shared timer structure behind one lock serializes every core that creates or cancels timers.
- tokio-109 | Hold one global timer for a whole collection of deadlines | A container that tracks many deadlines (a cache's TTLs, a retry queue) should keep its own local timer structure and hold a single registration with the global timer, for its earliest deadline.
- tokio-110 | Quantize time to integer ticks at the API edge | Convert wall-clock or monotonic instants into coarse integer ticks once, when a timer is created or reset.
- tokio-111 | Guard a rarely used time mode with a global "ever used" flag | If an expensive alternative clock (paused or mocked time) is almost never enabled, record its first use in a static atomic.
- tokio-112 | When firing everything, walk occupied slots directly instead of simulating time | A hierarchical timer structure normally advances level by level, cascading entries downward.
